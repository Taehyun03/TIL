## 네트워크의 구조
- 컴퓨터 네트워크
컴퓨터 네트워크는 컴퓨터끼리의 연결이다. (네트워크라는 말은 컴퓨터만 한정된 것이 아님)
컴퓨터가 2대 이상 연결되면 네트워크로 메시지 전송, 웹 사이트 방문 등 많은 일을 할 수 있게 된다.
여기서 인터넷은 거대한 네트워크를 말한다.

- 패킷
컴퓨터끼리 네트워크로 데이터를 주고 받으려면 규칙이 있어야한다. -> 패킷
네트워크를 통해 전송되는 데이터의 작은 조각으로, 택배로 비유된다.
네트워크 대역폭을 한번에 많이 차지하면 안되므로 패킷을 작게 나눠 보낸다.
작게 나눠 보낸 패킷이 도착하면 다시 복구시키는 작업을 해야한다. -> 순서가 뒤죽박죽인 대신 패킷마다 번호를 붙여 정렬.

## 정보의 양을 나타내는 단위
- 디지털 데이터
0과 1의 집합을 디지털 데이터라고 하며 데이터의 가장 최소단위는 비트이다. 그 비트가 8개 모이면 1바이트가 되며
컴퓨터는 바이트 단위로 데이터를 이해한다.
우리들이 사용하는 문자는 문자 코드로 이미 0과 1의 조합으로 정의되어있다. (문자도 문자코드에 따라 0과 1로 바뀐뒤
다른 데이터와 똑같이 패킷에 담겨 전송된다.)

## LAN 과 WAN
- LAN
건물이나 범위가 특정하게 제한된 네트워크(사무실내의 네트워크)
- WAN
ISP(인터넷 서비스 제공자 - 통신회사)가 제공하는 서비스를 사용해 구축된 네트워크 -> 사무실과 사무실을 연결하는 네트워크
속도도 LAN이빠르며 오류도 LAN이 더 적다. (짧은 네트워크이므로)

## 가정에서 하는 랜 구성
- ISP(인터넷 서비스 제공자 - 통신회사), 인터넷 회선
가정에서 인터넷을 사용하는 방법으로는 WIFI 가 대표적이다. 

보통 ISP와 네트워크 공유기 사이에 연결이 되어있고 그 공유기가 집안 네트워크 기기들을 연결하는데에 와이파이를 활용한다.

원래 ISP에서 집안 공유기마다 대표 공인 IP를 1개씩 주지만 네트워크 기기들은 1개를 훌쩍넘는다.

그래서 공유기가 와이파이가 연결된 네트워크 기기들에게 사설ip를 부여한다. (WIFI를 WLAN이라고 부름)

사설 ip로 데이터 요청을 하면 공유기로 전달되고 그 공유기가 공인 ip로 ISP에 데이터를 전달하는 방식이다. (핫스팟은 휴대폰이 공유기가 되는거임)

데이터는 일반 와이파이 방식과 다르게 휴대폰에서 공유기를 거치지 않고 지역마다 설치된 기지국으로 전달하여 그 기지국이 공인 ip로 데이터를 전달한다. (설치된 기지국이 큰 공유기 역할)

📤 5계층 기준 송신(캡슐화) 과정 정리

내 노트북에서 다른 기기(친구 PC, 서버 등)로 데이터를 보낼 때, 각 계층이 무엇을 하고 어떤 판단을 거치는지 트리 구조로 정리한 문서.

1. 전체 트리
📤 보내는 쪽 (예: 내 노트북 → 친구/서버)
│
├─ 5. 응용 계층
│   ├─ 보낼 데이터 생성 (HTTP 요청, 카톡 메시지, 파일 등)
│   ├─ 필요하면 암호화 (HTTPS 등)
│   └─ 목적지 이름이 도메인이면 → DNS로 목적지 IP 알아내기
│       결과: [데이터]
│
├─ 4. 전송 계층
│   ├─ 프로토콜 선택
│   │   ├─ TCP: 연결 맺고, 순서·누락 관리 (웹, 카톡, 파일)
│   │   └─ UDP: 확인 없이 빠르게 (영상, 게임, DNS)
│   ├─ 출발지 포트 (내 프로그램) / 목적지 포트 (상대 프로그램)
│   └─ 데이터가 크면 잘라서 나눔
│       결과: [TCP/UDP 헤더][데이터]  ← 세그먼트
│
├─ 3. 네트워크 계층
│   ├─ 출발지 IP (내 IP) / 목적지 IP (최종 목적지)
│   ├─ TTL 등 설정
│   ├─ 🔀 판단: 목적지가 우리 네트워크인가? (내 IP + 서브넷 마스크)
│   │   ├─ YES → 다음 정거장 = 목적지 기기 자신
│   │   └─ NO  → 다음 정거장 = 기본 게이트웨이(공유기)
│   └─ 🔍 다음 정거장의 MAC 찾기 (ARP)
│       ├─ ARP 테이블에 있음 → 바로 사용
│       └─ 없음 → ARP 요청(브로드캐스트) → 응답 받고 저장 → 사용
│       결과: [IP 헤더][TCP 헤더][데이터]  ← 패킷
│
├─ 2. 데이터링크 계층
│   ├─ 목적지 MAC (다음 정거장) / 출발지 MAC (내 랜카드)
│   ├─ 타입 (IPv4 = 0x0800)
│   ├─ 뒤에 FCS (오류 검사값)
│   └─ 매체 규칙 선택
│       ├─ 유선 → 이더넷 프레임
│       └─ 무선 → 와이파이 프레임
│       결과: [MAC 헤더][IP 헤더][TCP 헤더][데이터][FCS]  ← 프레임
│
└─ 1. 물리 계층
    ├─ 프레임의 0과 1 → 실제 신호로 변환
    │   ├─ 랜선     → 전기 신호
    │   ├─ 광케이블 → 빛 신호
    │   └─ 와이파이 → 전파
    └─ 전송 🚀
        결과: 신호 (비트)
2. 계층별 요약
계층	붙이는 것	데이터 단위	주소	대표 프로토콜
5. 응용	데이터	메시지	도메인 이름	HTTP(S), DNS, DHCP
4. 전송	TCP/UDP 헤더	세그먼트	포트 번호	TCP, UDP
3. 네트워크	IP 헤더	패킷	IP 주소	IPv4, IPv6, ICMP
2. 데이터링크	MAC 헤더 + FCS(트레일러)	프레임	MAC 주소	이더넷, 와이파이
1. 물리	(신호 변환, 동기화용 프리앰블)	비트	없음	이더넷·와이파이 물리 규격
ARP는 IP 주소(3계층) → MAC 주소(2계층)를 알아내는 다리 역할 (이더넷 타입 0x0806)
ARP 메시지는 IP 헤더 없이 이더넷 프레임에 바로 담긴다
3. 핵심 포인트
IP 주소 vs MAC 주소
[MAC 헤더: 목적지 = 다음 정거장][IP 헤더: 목적지 = 최종 목적지][TCP][데이터][FCS]
	IP 주소 (3계층)	MAC 주소 (2계층)
의미	최종 목적지	바로 다음 정거장
경로 중 변화	유지됨 (NAT 구간 제외)	라우터를 지날 때마다 바뀜
가장 중요한 갈림길: 3계층의 🔀 판단
목적지가 같은 네트워크 → 목적지 MAC = 상대 기기 MAC
목적지가 다른 네트워크(인터넷) → 목적지 MAC = 공유기(게이트웨이) MAC
라우터의 IP는 패킷에 적히지 않음. 라우터 MAC을 ARP로 알아내는 데만 쓰임
전체 흐름 한 줄 요약
내 컴퓨터(전부 캡슐화) → 라우터 → 라우터 → … → 목적지(전부 역캡슐화)
중간 장비는 필요한 계층까지만 역캡슐화
허브·리피터: 1계층 (신호만)
스위치: 2계층 (MAC)
라우터: 3계층 (IP) / NAT는 4계층 포트까지
목적지가 장비 자신이면 응용 계층까지 끝까지 역캡슐화
